# Support Team Daily Activity Tracker

A Laravel application for tracking the daily activities of an applications support team. Team members record the status of each activity (done/pending), add remarks, and the system captures who made the update and when — enabling daily handover and historical reporting.

## Requirements Coverage

| # | Requirement | Implementation |
|---|---|---|
| 1 | Input activities (e.g. "Daily SMS count in comparison to SMS count from logs") | `Activity` model with name/description/category/frequency; admin-managed CRUD under **Manage Activities**. |
| 2 | Update status (done/pending) + remark per activity | **My Daily Tracker** — one update per activity per day (upsert), with optional remark. |
| 3 | Capture bio details of personnel + time done | `users` bio fields (staff ID, department, phone); each update stores `user_id` and timestamps (`created_at`/`updated_at`) automatically. |
| 4 | Daily view of all activities/updates (handover of pending work) | **Daily Handover** — personnel × activity matrix for any date, showing status, remark and update time. |
| 5 | Reporting over custom date ranges | **Reports** — filter activity history by from/to date, activity, personnel and status, with summary counts. |
| 6 | User authentication | Session-based auth (login/register/logout); all routes protected; activity management restricted to admins. |

## Tech Stack

- Laravel 13 (PHP 8.4)
- SQLite (file-based, zero-config) — MySQL/PostgreSQL supported via `.env`
- Tailwind CSS v4 (compiled with Vite)
- PHPUnit feature tests

## Setup

```bash
# 1. Install dependencies
composer install
npm install

# 2. Environment
copy .env.example .env   # Windows
php artisan key:generate

# 3. Database (SQLite)
# .env already uses sqlite; create the file if missing:
# (an empty database/database.sqlite is provided, or:)
#  type nul > database\database.sqlite

php artisan migrate --seed

# 4. Build frontend assets
npm run build

# 5. Run
php artisan serve
# → http://localhost:8000
```

## Deployment Notes

**Local/production server (PHP 8.1+):**

```bash
php artisan config:cache
php artisan route:cache
php artisan view:cache
php artisan serve --host=0.0.0.0 --port=80
```

**Production (Nginx/Apache):**
1. Point the web root at `public/` and route all requests to `public/index.php`.
2. Use a real RDBMS if preferred: set `DB_CONNECTION=mysql` in `.env` and run `php artisan migrate --seed`.
3. Set `APP_ENV=production` and `APP_DEBUG=false`, then run `php artisan migrate` (skip `--seed` or use it for first-time demo data).
4. Schedule queue worker if job-based notifications are added later.

**Security defaults baked in:** password hashing, CSRF protection, session-based auth, input validation on every endpoint, and an admin-only middleware (`admin`) guarding activity management.

## Deploy to Render

Render deploys the app from a **Docker** web service (PHP 8.3 + Nginx + php-fpm) with a managed **PostgreSQL** database, driven by the `render.yaml` blueprint in this repo (works on the free tier; free Postgres is deleted after ~90 days).

1. Push this repo to GitHub:
   ```bash
   git init && git add . && git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<you>/<repo>.git
   git push -u origin main
   ```
2. In the [Render Dashboard](https://dashboard.render.com), click **New + → Blueprint**.
3. Connect your GitHub account and select this repository (branch `main`).
4. Click **Apply**. Render provisions the Postgres database, builds the Docker image, and on container start runs migrations + seeds (`docker-entrypoint.sh`) and serves the app via Nginx.
5. Open the service URL and log in with `admin@support.local` / `password` (seeded on first start).

Notes:
- `APP_KEY` is auto-generated by Render (`generateValue: true`). Never commit a real `APP_KEY`.
- Production uses `DB_CONNECTION=pgsql` via `DB_URL` injected from the database service. Local dev keeps SQLite (`.env`).
- `APP_URL` is derived from Render's service URL; proxy headers are trusted (`bootstrap/app.php`).
- The first deploy may take 5–10 minutes. Subsequent pushes to `main` auto-deploy.
- Migrations + idempotent seeding run at every container start, so data survives redeploys.
